Evaluation protocol

FluidBench runs training and prediction through a shared benchmark workflow. A submission implements the model interface; the benchmark provides its data splits, calls the model, maps predictions to the comparison locations when required, and calculates the selected metrics.

  1. 1
    Load a benchmark

    Use the benchmark's shared training, validation, and test splits.

  2. 2
    Fit the model

    Receive training data and configuration through fit().

  3. 3
    Predict the horizon

    Provide input snapshots and return the requested future time steps.

  4. 4
    Calculate and record

    Compute comparable metrics and record the run configuration and environment.

Tensor layout

Input and output shapes

Batch and time dimensions are shared. Matrix inputs use structured spatial grids; Graph inputs use an unstructured set of mesh nodes.

RepresentationInput xOptional scalarsPrediction y
Matrix[B, Tin, H, W, Cin][B, Tin, Nscalar][B, Tout, H, W, Cout]
Graph[B, Tin, N, C][B, Tin, Nscalar][B, Tout, N, Cout]

B is batch size, Tin input steps, Tout predicted steps, and N mesh nodes.

Reproducibility

Configuration

Include model and training parameters such as optimizer, learning rate, epoch count, and batch size.

Random seed

Record the seed used for initialization, data order, and any stochastic training steps.

Environment

Record Python, framework, accelerator, and relevant dependency versions.

Example run record: config.json, seed: 42, and an environment summary.
